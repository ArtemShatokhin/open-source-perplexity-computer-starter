# Skill: cite sources

This skill ships with the open source Kortix starter. Use it whenever a researched claim goes into a report. Its job is to keep the difference visible between what a source states and what the agent inferred, so a reader can check any claim without redoing the whole search.

## When to use it

Apply it to every fact a reader might doubt: a competitor's licence, a price, a limit, a release, a version, a statistic or a capability. Also apply it to any claim about Kortix, since the product documentation is the only authority for what Kortix does.

## Rules

1. Cite the primary source, not a summary of it. A repository, an official product page or a documentation page is primary; a listicle that quotes one is not.
2. Link the claim once, at the point of use, so the claim and its evidence sit in the same sentence or the one after it.
3. Record the date the source was checked when the fact can change, such as a price, a star count or a version. Leave that date out of headings.
4. Keep sources out of comparison-table cells. Put the source links in the prose around the table instead, so the table stays readable and each cell answers its column header.
5. Mark inference as inference. If you reasoned from evidence rather than reading it, say so, and never let an inference read as a quoted fact.
6. When no source documents a fact, say the sources do not cover it. Do not fill the gap with a plausible guess or leave an unsourced claim standing.
7. Never invent a citation, a URL, a URL path, a quotation or a number. A missing citation is a smaller problem than a fabricated one.

## Output

For each claim, keep three things together: the claim, the source URL, and the date checked where relevant. A report that follows this skill can be verified claim by claim and quoted passage by passage.
